## 2. Information Security & Cryptography (NFR-SEC)

### 2.1 Cryptographic Standards
- **NFR-SEC-01 (Token Entropy):** All parent invitation tokens generated by `crypto.randomBytes(32)` must contain at least 256 bits of cryptographic entropy.
- **NFR-SEC-02 (Storage Hashing):** Raw parent invitation tokens must never be written to Firestore. The server must store only the 64-character hexadecimal SHA-256 hash.
- **NFR-SEC-03 (Session Signing):** Parent upload session tokens must be signed using HMAC-SHA256 with an ephemeral or environment secret, embedding student ID, allowed document slots, and expiration timestamp.
- **NFR-SEC-04 (Storage Privacy):** All student documents uploaded to Vercel Blob storage must have `access: "private"`. No public bucket or unauthenticated object access is permitted.
- **NFR-SEC-05 (URL Expiration):** Presigned document download URLs must enforce a maximum lifetime of 300 seconds (5 minutes).
- **NFR-SEC-06 (Google Service Account Identity):** Serverless Firestore writes from Vercel must authenticate using RS256 JWT exchange for Google OAuth 2.0 access tokens (`https://www.googleapis.com/auth/datastore`).

### 2.2 Data Privacy & PII Protection
- **NFR-SEC-07 (Privacy Minimization):** Parent mobile numbers must not be recorded in document upload metadata or audit logs. Uploads must record actor identity as `parent_invite_<tokenHashPrefix>`.
- **NFR-SEC-08 (URL Hash Scrubbing):** When a parent opens a document link containing a token hash `#t=...`, the client must scrub the hash immediately from `window.location` using `history.replaceState` to prevent token leakage via referrer headers or browser history.
- **NFR-SEC-09 (Session Storage Isolation):** Parent upload session tokens must be maintained strictly in volatile React state or memory, and never persisted in `localStorage` or `sessionStorage`.

## 3. Reliability & Fault Tolerance (NFR-REL)

- **NFR-REL-01 (Self-Healing Auth):** If a staff document in Firestore has mismatched role attributes (such as the P0 incident where `developer@hanujai.edu.in` was saved with `role: "admin"`), the authentication layer must automatically detect the discrepancy and reconcile Firestore to the authorized role.
- **NFR-REL-02 (Fail-Closed Authorization):** Missing staff records, inactive accounts, or malformed auth tokens must result in immediate rejection (HTTP 401/403) rather than fallback to lower privilege roles.
- **NFR-REL-03 (Audit Trail Immutability):** The `auditEvents` Firestore collection must be append-only. `firestore.rules` must explicitly deny `update` and `delete` operations for all users including administrators.
- **NFR-REL-04 (WhatsApp Worker Crash Recovery):** The WhatsApp worker queue must survive network drops or process restarts, resuming pending jobs from Firestore without dropping or duplicating messages.

## 4. Scalability & Operational Capacity (NFR-SCALE)

- **NFR-SCALE-01 (Student Ledger Volume):** The database and UI must comfortably handle 1,000 active student records across 20 class sections (Nursery through Class 10, sections A and B).
- **NFR-SCALE-02 (Concurrent Daily Register Submissions):** The serverless backend must handle simultaneous register submissions from all 20 classes during the morning attendance window (08:00 - 08:30 IST) without rate throttling or locking conflicts.
- **NFR-SCALE-03 (Document Ingestion Throughput):** Document storage architecture must support bulk ingestion of up to 9,000 documents (9 slots × 1,000 students) with zero degradation of upload speeds.

## 5. High Availability & Disaster Recovery (NFR-AVAIL)

- **NFR-AVAIL-01 (Uptime Service Level):** Platform target of 99.9% uptime backed by Vercel Edge Network and multi-region Google Cloud Firestore (`asia-south1` Mumbai).
- **NFR-AVAIL-02 (Database Backup & Snapshots):** Developer Console must provide one-click database snapshot exports with pre-migration recovery capability.
- **NFR-AVAIL-03 (Zero-Downtime Deployments):** Production deployments on Vercel must utilize immutable atomic preview builds with instant rollback capabilities.

## 6. Mobile Usability & Responsive Ergonomics (NFR-RESP)

- **NFR-RESP-01 (Target Viewports):** Flawless responsive layout verified on:
  - 375px × 667px (iPhone SE)
  - 390px × 844px (iPhone 13 / 14 / 15 standard)
  - 430px × 932px (iPhone 15 / 16 Pro Max)
  - 768px × 1024px (iPad / Tablet)
- **NFR-RESP-02 (Apple Safari Touch Ergonomics):** Minimum touch target size of 44px × 44px for all mobile interactive elements (buttons, segmented controls, toggles).
- **NFR-RESP-03 (iOS Safe Area Compliance):** Full support for dynamic viewports (`100dvh`) and safe area insets (`env(safe-area-inset-top)`, `env(safe-area-inset-bottom)`) to prevent home bar and notch collisions.
- **NFR-RESP-04 (Form Zoom Prevention):** Mobile input fields must enforce a minimum font size of 16px to prevent iOS Safari from automatically zooming the page on focus.

---

## 7. Accessibility Standards (NFR-A11Y)

- **NFR-A11Y-01 (WCAG 2.1 AA Compliance):** Color contrast ratio of at least 4.5:1 for normal text and 3:1 for large text across the entire design system (`#0A1931`, `#1E293B`, `#FFFFFF`, `#10B981`, `#EF4444`).
- **NFR-A11Y-02 (Keyboard Navigation):** Full keyboard navigability across all data entry forms, modals, drawers, and tab switchers with visible focus outlines.
- **NFR-A11Y-03 (Screen Reader Compatibility):** Appropriate ARIA attributes (`aria-label`, `aria-expanded`, `aria-hidden`, `role="table"`) for dynamic controls and segmented filters.
